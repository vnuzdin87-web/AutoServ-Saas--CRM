# АвтоСервис CRM — техническая спецификация MVP

Локальная CRM для приёмки автомобилей, ведения заказ-нарядов и учёта оплат.

## Локальная архитектура

Приложение использует Node.js 24, SQLite и браузерный JavaScript без установки пакетов. Сервер слушает `127.0.0.1:4178`. `GET /` отдаёт интерфейс. `GET /health` проверяет чтение состояния миграций. Перед обновлением существующей базы сервер создаёт SQLite-снимок. Миграции выполняются в транзакции с проверкой внешних ключей. При повторном запуске применённые миграции пропускаются.

## Модель данных

| Сущность | Поля и связи |
| --- | --- |
| Клиент | Имя, телефон, email, предпочтение по связи |
| Автомобиль | Клиент, марка, модель, госномер, необязательный уникальный VIN |
| Мастер | Имя, телефон, специализация, активность |
| Заказ-наряд | Уникальный положительный номер, клиент, автомобиль этого клиента, мастер-приёмщик, обещанная выдача, дата создания, обращение, статус |
| Позиция сметы | Наряд, вид «работа» или «запчасть», описание, сумма строки в целых копейках от нуля |
| История статусов | Наряд, прежний и новый статус, отметка времени, признак перенесённого статуса |
| Платёж | Наряд, сумма в целых копейках, момент получения, комментарий, ключ повторного запроса |
| Настройки | Название, телефон, адрес автосервиса |

ID выдаёт SQLite. Номер в интерфейсе выглядит как «ЗН-248». Для перенесённых заказов мастер создаётся по существующему текстовому имени, а текущий статус добавляется в журнал с отметкой переноса. Новые переходы записываются автоматически. Неактивного мастера можно сохранить в существующем назначении. Смена владельца автомобиля с заказами ограничена ради истории и ссылочной целостности. Госномер и контакты могут отсутствовать.

## Жизненный цикл заказ-наряда

| Статус | Допустимые переходы |
| --- | --- |
| Принят | В работе, Ожидает запчасти, Отменён |
| В работе | Ожидает запчасти, Готов к выдаче, Отменён |
| Ожидает запчасти | В работе, Отменён |
| Готов к выдаче | В работе, Закрыт, Отменён |
| Закрыт | Конечный статус |
| Отменён | Конечный статус |

Новый заказ получает статус «Принят». База проверяет перечень статусов, API применяет таблицу переходов. Недопустимый переход отклоняется с HTTP 409. Обещанное время передаётся из формы в московском времени, в базе сохраняется со смещением `+03:00`. Смета поддерживает до 100 позиций.

## Финансы

Стоимость заказа равна сумме позиций. Получено — сумма платежей. Долг — разница между стоимостью и полученными платежами, включая закрытые неоплаченные заказы. Отменённый заказ исключается из задолженности. Сервер отклоняет переплату, уменьшение сметы ниже полученной оплаты и отмену заказа с платежами. Возвраты в MVP отсутствуют. Предоплата и последующие частичные платежи используют один журнал. Повтор запроса с тем же идентификатором сохраняет один платёж.

## Маршруты API

| Метод и путь | Назначение |
| --- | --- |
| GET /api/v1/dashboard | Текущая дата по Москве, оперативные показатели, приёмка за семь дней, ближайшие выдачи и последние заказы |
| GET /api/v1/orders | Список, поиск, фильтр по статусу |
| POST /api/v1/orders | Приёмка и создание наряда |
| GET, PATCH /api/v1/orders/:id | Чтение и изменение наряда, включая позиции в одной транзакции |
| POST /api/v1/orders/:id/payments | Предоплата или частичный платёж |
| GET, POST /api/v1/customers | Поиск и создание клиента |
| GET, PATCH /api/v1/customers/:id | Карточка, автомобили, история и изменение контактов |
| POST /api/v1/customers/:id/vehicles | Добавление автомобиля клиента |
| GET, POST /api/v1/vehicles | Поиск и создание автомобиля |
| GET, PATCH /api/v1/vehicles/:id | Карточка, история и редактирование автомобиля |
| GET, POST /api/v1/masters | Справочник и создание мастера |
| GET, PATCH /api/v1/masters/:id | Карточка, заказы и редактирование мастера |
| GET /api/v1/finance | Сметы, оплаты, задолженность, история и фильтр должников |
| GET, PATCH /api/v1/settings | Реквизиты автосервиса |
| GET /api/v1/backup | Скачать целостный SQLite-снимок |
| POST /api/v1/backup/check | Проверить файл и получить сводку перед подтверждением |
| POST /api/v1/backup/restore | Восстановить проверенный файл после подтверждения |

Главная использует текущее время сервера. Приёмка включает сегодня и шесть предыдущих календарных дней по Москве. Открытые заказы исключают закрытые и отменённые. Просроченные — открытые, срок выдачи которых уже прошёл. Ближайшие выдачи — до пяти открытых заказов по возрастанию будущего срока. Последние заказы — до пяти нарядов в порядке убывания даты создания. Платежи за день считаются по московской дате получения.

Ручное восстановление принимает SQLite-файлы текущей версии до 16 МБ. Проверяются схема, версия миграций, целостность и связи. Файл проверяется повторно при подтверждении. Перед заменой создаётся страховочный снимок текущей базы. Данные восстанавливаются в одной транзакции.
